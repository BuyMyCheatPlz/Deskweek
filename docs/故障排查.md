# 故障排查与常见问题

如果你在使用 DeskWeek 时遇到问题，请先参考以下常见场景与排查建议。

> **重要提示**：排查问题时，请**不要**随意删除 `data/` 文件夹。你的所有日程和待办数据都保存在这里。

---

## 1. 浮窗看不到了，但托盘图标还在

### 可能原因与解决方法

- **当前有全屏程序运行**：
  - 当浮窗所在屏幕被全屏游戏、视频或演示覆盖时，浮窗才会暂时休眠。另一块显示器全屏时，仍可见的浮窗应继续刷新并保持显示。
  - **解决办法**：退出全屏状态后，浮窗会在 1~2 秒内自动重新显示。
- **浮窗被其他常规窗口遮挡**：
  - DeskWeek 的浮窗位于桌面背景层之上、普通软件窗口之下，不会抢占焦点。如果有浏览器、文档等窗口遮挡桌面，浮窗会被挡在后面。
  - **解决办法**：按快捷键 `Win + D` 返回桌面，或最小化当前打开的窗口即可看到。
- **更换显示器或分辨率后浮窗跑出屏幕外**：
  - 如果你拔掉了副屏，或者调整了屏幕分辨率，浮窗可能停留在旧坐标位置。
  - **解决办法**：右键屏幕右下角的 DeskWeek 托盘图标，选择 **“找回浮窗并重置位置”**，浮窗会立刻回到主屏幕居中位置。
- **之前手动隐藏了浮窗**：
  - 右键托盘图标，点击 **“显示/隐藏浮窗”** 即可重新唤出。
- **查看当前状态**：
  - 右键托盘图标可以查看“浮窗状态”。如果显示“暂停刷新”，说明浮窗所在屏幕被全屏程序覆盖、浮窗被手动隐藏，或电脑正处于锁屏状态。

## 2. 点击显示后，浮窗只闪一下就消失

### 问题说明
某些显卡工具（如 NVIDIA 游戏覆盖层 / 滤镜）或多屏增强软件（如 DisplayFusion）会在后台创建全屏大小的透明辅助窗口。早先版本的全屏检测只检查了窗口尺寸，可能会将这类透明窗口误判为“全屏游戏”，从而让浮窗进入了休眠状态。

### 解决方法
1. **使用最新版本**：新版已优化全屏检测算法，能准确识别并忽略此类后台全透明窗口。
2. **彻底退出旧进程**：如果刚刚更新了程序，请先打开任务管理器确认完全退出了旧版 DeskWeek 进程，再启动新版本。
3. **临时测试**：尝试临时退出显卡滤镜软件或动态壁纸，观察浮窗是否能稳定保持。

## 3. 从全屏切回时弹出错误提示（Object has been destroyed）

### 问题说明
在极快速切换全屏、或者在浮窗正在加载的瞬间立刻关闭/休眠时，窗口后台加载通知可能会遇到窗口已经提前关闭的情况，导致系统报出 `Object has been destroyed` 提示。

### 解决方法
- 最新版本已全面增加了窗口状态安全检查，关闭窗口时会自动清理旧的加载通知，避免该问题。
- 建议升级到最新版。若遇到此提示，直接点击确认并重启程序即可，已保存的日程数据不会受到任何影响。

---

## 4. 与 Wallpaper Engine 动态壁纸同时运行时被盖住

### 问题说明
DeskWeek 设计为直接贴合在桌面背景上，正常情况下会浮在壁纸之上、桌面图标之后。但在切换壁纸或重启壁纸软件时，壁纸软件可能会重新排布桌面的前后顺序，偶尔将浮窗盖住。

### 解决方法
1. **一键唤回**：右键右下角托盘图标，点击 **“找回浮窗并重置位置”**，即可重新将浮窗唤回到壁纸的最前层。
2. **壁纸软件设置**：在 Wallpaper Engine 的设置中，保持动态壁纸作为普通的桌面背景运行，避免勾选“置顶显示”等特殊选项。

## 5. 全屏后内存没有清零，或切回桌面时需等待 1~2 秒

### 现象说明
- **为什么切回时要等 1~2 秒**：当你长时间全屏打游戏或离开电脑时，浮窗为了节约内存，会自动释放占用较多的界面渲染器；切回桌面时，浮窗需要重新绘制界面和卡片，耗时约 1~2 秒，属于完全正常的节能设计。
- **为什么内存没有完全清零**：后台依然保留了非常轻量的主进程与系统托盘图标，以便随时接收快捷键和全屏唤醒通知。
- **内容保护优先**：如果浮窗上有你正在输入但尚未保存的文字，程序绝不会强行关闭界面，优先确保内容不丢失。

## 6. 保存提示冲突、文件损坏或备份恢复

### 解决方法
- **两个窗口修改了同一条任务**：
  - 如果在管理中心和桌面浮窗同时编辑了同一条事项，若修改的是不同内容，程序会自动合并；若修改了同一处文字，会弹窗提示你选择保留哪一份修改。
- **提示数据文件损坏**：
  - DeskWeek 每次保存都会自动生成备份。若主数据文件意外损坏，程序会自动尝试读取最新的 `.backup` 备份文件，并将损坏文件重命名留存（如 `data.json.corrupt-时间戳`），绝不会以空白内容覆盖已有数据。
- **保存权限报错**：
  - 请确认 DeskWeek 所在文件夹具备读写权限。建议将便携版解压至普通文件夹（如 `D:\Tools\DeskWeek`），避免放在受 Windows 严格保护的系统目录（如 `C:\Program Files`）中。

## 7. 检查更新失败（403）或自动下载失败

### 问题说明
DeskWeek 通过 GitHub 官方接口检查并下载更新。国内网络访问 GitHub 时偶尔可能出现连接超时或 HTTP 403 频率限制错误。

### 解决方法
1. **手动更新**：直接访问 [GitHub Releases](https://github.com/EasonGuuu/Deskweek/releases) 下载最新版本的压缩包。
2. **无缝覆盖**：解压新版本前，将旧版本中的 `data/` 文件夹复制到新版本目录下，即可完整保留你的所有日程、设置与开机自启选项。

## 8. 开发者：源码运行或打包报错

- **运行没有弹出窗口**：
  - 使用 `npm start` 启动项目。如果直接调用 Electron 可执行文件，请检查环境变量中是否残留了 `ELECTRON_RUN_AS_NODE=1`，该变量会导致 Electron 进入纯命令行 Node 模式而无法显示窗口。
- **打包时下载失败**：
  - 打包工具需要从网络拉取 Electron 依赖包，请检查网络连接或配置相应的 npm/electron 镜像源。
- **避免打包覆盖数据**：
  - 打包过程会自动清理目标文件夹，请务必设置独立的输出目录（如 `DESKWEEK_BUILD_DIR='dist/build-verify'`），千万不要将输出路径指向自己正在使用、包含实际日程数据的便携文件夹。

## 9. 报告问题时的建议

如果遇到无法解决的问题，欢迎前往 GitHub Issues 提交反馈。提供以下信息有助于更快定位原因：

- **运行方式**：使用的是 GitHub Releases 发布的便携版还是自己通过源码启动。
- **具体现象**：问题的复现步骤、现象描述或截图，以及具体的报错文字。
- **系统环境**：Windows 版本、显示器数量及缩放比例（DPI）、是否正在运行 Wallpaper Engine 或特定显卡录屏工具。

> 隐私提示：提交日志或截图前，请注意遮挡 API Key 或个人的私密日程内容。
