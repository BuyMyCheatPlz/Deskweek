# Android 移动端协同与局域网多端同步方案

本文档介绍了 DeskWeek Windows 桌面版与 Android 移动端（手机与平板）之间的协同工作原理与局域网同步方案。

---

## 一、双端形态与协同目标

DeskWeek 致力于为用户提供纯粹、安静、本地优先的周历待办体验：

- **Windows 桌面版**：直接贴合在系统桌面背景上，不破坏现有壁纸，无需频繁切换窗口即可一览本周日程；自带强大的管理中心，方便高效输入与归纳整理。
- **Android 移动端**：提供原生 Android 应用与全透明桌面周历小组件，支持手机与平板自适应，随时随地在桌面查看和完成任务。
- **跨端协同**：无需云端注册与登录，两端既可通过标准的本地 `data.json` 文件自由导入导出，也可在连接同一家庭/办公 Wi-Fi 时自动发现并进行点对点增量同步。

配套开源仓库：[BuyMyCheatPlz/DeskWeek-Android](https://github.com/BuyMyCheatPlz/DeskWeek-Android)

## 二、数据格式与文件互通

两端遵循统一的日程数据结构（`data.json`），包含以下关键要素：

1. **核心任务模型**：
   - `id`：全局唯一任务标识（UUID）。
   - `title`：任务标题。
   - `memo`：详细备注说明。
   - `date`：所属日期（`YYYY-MM-DD` 格式，支持空日期作为暂缓/未排期任务）。
   - `time`：具体时间（`HH:mm` 格式）。
   - `done` 与 `completedAt`：完成状态与完成时间戳。
   - `defer`：提前提醒规则（如提前 1 天、3 天或 1 个月）。
   - `deleted`：软删除标记（支持移入废纸篓与恢复）。
2. **导入与导出**：
   - 用户可以在 Windows 端随时导出 `data.json`，在手机端直接导入（支持“合并导入”或“替换导入”）；反之亦然。
   - 导入时具备数据完整性与损坏保护校验，确保异常文件不会影响已有日程。

## 三、局域网点对点同步协议

为了彻底摆脱对第三方云服务的依赖，保护用户个人隐私，DeskWeek 设计了去中心化的局域网直连同步机制：

### 1. 局域网服务发现（mDNS / DNS-SD）
- 开启同步的设备会在局域网内通过标准 mDNS 广播服务：
  - **服务标识**：`_deskweek-sync._tcp`
  - **动态端口**：系统动态分配空闲端口。
  - **广播内容**：仅广播协议版本与配对组标识，绝不广播任何日程文本或敏感信息。
- 手机端或桌面端在同一 Wi-Fi 下可一键搜索发现对方设备。

### 2. 端到端加密与安全配对
- **TLS 加密通道**：两端直连通信全程运行在 TLS 1.2 / TLS 1.3 之上，防止局域网内被监听或中间人攻击。
- **证书指纹固定**：首次配对时双方核验安全码并记录对方的证书指纹，完成身份绑定；后续重连自动验证，无需重复操作。

### 3. 增量操作与离线合并
- 每次新建、编辑、完成或改期均生成一条轻量的原子操作记录。
- 设备在重连局域网后互相交换对方缺失的操作：
  - **不同字段改动**：自动合并，两端均得到最新结果。
  - **直接文本冲突**：保留双方候选内容，并弹窗提示用户选择保留哪一份，避免信息丢失。
  - **对等互通**：手机与平板之间也是平等对等关系，即使电脑关机，手机和平板在同一局域网下仍可顺畅同步。

## 四、本地独立配置隔离

同步协议严格聚焦于日常任务与日程信息，以下各项配置保持在各设备本地，彼此独立：

- **桌面浮窗 / 窗口位置与尺寸**：每台电脑与手机的屏幕尺寸与分辨率不同，各自记忆最佳显示位置。
- **小组件与浮窗背景透明度**：根据各自设备的桌面壁纸特点自由选择标准底板或全透明模式。
- **AI 助手配置与 API Key**：API Key 仅保存在本机安全存储中，绝不通过网络同步外流。
